DISCOPT_HIGHS_SEPA_CUTOFF_BOX -- why the ported separators returned 0 cuts on gsvm2rl3
(2026-11-11; branch off claude/sleepy-gates-8ronyd @ 2ef4b8d5)

Question: on gsvm2rl3 (180 rows, 241 cols, 60 binaries) `bridge::separate_node` returned 0
cuts at every node (NodeGmiRaw 0), and the root's ported separation also generated 0
(SepCmirCuts 0), while HiGHS's root separates 55 cuts (bound 0.012 -> 0.031, log below).

Hypotheses from the task, with the measurement that decided each:
 (a) separation never reached -- FALSE. NodeGmiSep 13 calls / 200 nodes; the root ran
     7 rounds. Every call ran the separators.
 (b) every cut rejected by efficacy / density / numerics -- FALSE. Temporary counters in
     transform / generate_cut / finish (removed after the probe) per round:
       root:  transform calls 3434-3942, refused for a FREE COLUMN 3434-3942 (100 %),
              transformed 0, core/untransform/postprocess/pool rejections 0.
       tableau: 7-31 fractional basics scored, all skipped before generate_cut by the
              aggregation-dynamism test (max/min |coef| > 1e6) -- HiGHS has the same test.
       nodes: identical shape (100 % free-column refusals).
 (c) the LP handed to the bridge differs from HiGHS's -- TRUE, in its column BOUNDS.
     The view had 61 free structural columns (b and u_1..u_60). In the model u_k is bounded
     only through s_k >= |u_k| and s_k's objective cost: HiGHS's transformed LP reads the
     global domain (HighsTransformedLp.cpp:45-67), and that domain propagates the objective
     row c x <= upper_limit once an incumbent exists (HighsMipSolverData.cpp:980
     setupObjectivePropagation). HiGHS has the incumbent 0.6 before its first separation
     round ("S" row at node 0), so s_k <= 0.6, |u_k| <= 0.6, b >= finite, and the
     aggregations transform. discopt handed the separators the root box alone.

Fix (flag DISCOPT_HIGHS_SEPA_CUTOFF_BOX, default OFF):
 - root rounds and node rounds separate over FBBT(global rows + c x <= incumbent - obj_const,
   rounded up) -- never HiGHS's strict incumbent - feastol -- so every cut is valid for all
   points at least as good as the incumbent (the guarantee RC fixing already relies on);
 - in the node-separation arm, an NS abstention on the optimal local LP no longer abandons
   the node's rounds: the point is kept for separation, no bound is recorded. Measured on
   gsvm2rl3 at 2000 nodes with the box alone: NS abstained on 22/22 local solves (20 of them
   the inherited-pool solve that precedes separation), so only 5 node rounds ran.

Soundness: DISCOPT_HIGHS_SEPA_CHECK_POINT with gsvm2rl3's optimum (HiGHS, 0.33652753396,
max viol 2.0e-11, permuted to the driver's column order), 2000 nodes, flag ON:
