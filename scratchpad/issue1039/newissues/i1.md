## Summary

On the geometric-programming corpus, `min x/y + y/x` returns

```
objective = 1.998683979470214   status = optimal
```

The true global minimum is exactly **2** (AM-GM: `t + 1/t >= 2` for `t > 0`).
The reported objective is **below** the global minimum, and the status is
`optimal`, so this is a false certificate — the highest-severity class under
CLAUDE.md §1, not an accuracy complaint.

## The reported value is not the objective at the returned point

The distinguishing measurement: evaluate the objective in plain Python at the
solver's own returned incumbent.

```
returned objective   1.998683979470214
oracle at that point 2.000002247829649
delta               -1.318268e-03
```

So the solver is not merely finding a slightly-infeasible point and reporting
its true value; it is reporting a number that **no point attains**, its own
incumbent included. `objective` and `x` disagree.

## It is specific to division

Running the same comparison across the corpus's expression families, only the
quotient forms mismatch:

| family | max |reported − oracle at returned point| |
|---|---|
| affine | <= 4e-16 |
| bilinear | <= 4e-16 |
| separable square | <= 4e-16 |
| **division** | **1.3e-03** |

## The error scales as 1/denominator, so it is unbounded

`|delta| x denominator` is flat at approximately **1.9e-6** across denominator
floors of 1e-3 and 1e-2. That is the absolute constraint tolerance (1e-6)
amplified by `1/y`: a point that violates the defining equality of a quotient
aux by `eps` moves the quotient's value by `eps/y`. As `y -> 0` the reported
objective can be arbitrarily far below the true optimum, so no fixed tolerance
widening bounds this.

## Where it is

The returned value does not pass through any Python frame — a frame-level trace
over the solve shows zero Python returns of `1.998683979470214`. It comes from
the Rust incumbent path, which accepts a point as feasible under the absolute
tolerance and records the *relaxation's* objective value for it rather than
re-evaluating the true objective at the accepted point.

## Definition of done

The reported `objective` must equal the objective evaluated at the reported `x`,
to within a documented tolerance that does not depend on the magnitude of an
intermediate denominator. The likely correct fix is to re-evaluate the true
objective at an incumbent when it is accepted, and to treat a quotient aux whose
denominator is near its bound as not-yet-feasible rather than tolerance-feasible.
